# Review, October 2026: search quality and the web UI

An independent review of rummage running on a real personal library (about 4,500 files and
10,000 vectors: phone photos and videos, music stems, notes and PDFs) on an AMD Radeon 8060S
with the Vulkan build. The detailed query lists, judgments and screenshots are kept private
because they show personal files; this page keeps the method, the numbers and the findings.

## Cross-kind ranking (fixed in #11)

**The problem.** Scores are not comparable across kinds: a music query scores every music stem
high, and the sound track of an ordinary phone video (wind, street noise) sits close to many
text queries. So audio files almost never reached the mixed results, and generic sound tracks
outranked video frames that actually matched.

**What changed.** Text queries are calibrated against 212 generic probe queries
(`crates/rummage-core/src/probes.rs`), embedded once on the first text search: a hit's cosine is
ranked by `(cosine - mean cosine to the probes) / sqrt(spread)`. Item and file searches keep the
per-kind z-score. A hit whose segment is a near copy (cosine >= 0.99, same kind) of a better
hit's moves behind the distinct hits.

**Before and after** (same database snapshot, both binaries, hybrid search, 24 results):

| measure | before | after |
|---|---:|---:|
| top-3 right over 18 judged photo/video/note/PDF queries | 35.5/54 | 44/54 |
| sound queries with a right audio file in the mixed top 10 | 0/11 | 8/11 |
| visual queries filtered to video whose top hit matches on a frame | 48/90 | 79/90 |
| search latency p50 | 9.0 ms | 9.2 ms |

No reindex was needed.

## Using it

Across 22 typical searches started from a dashboard search box, 20 answers were on the first
screen one click away, and none needed more than 2 clicks. Results appear about 180 ms after
the last keystroke, a preview is ready in a median of 108 ms, and video and audio seek to
within 0.6 s of the matched moment. Desktop and phone, light and dark, empty, error and
keyboard-only states were checked.

## HEVC playback and plural-aware keywords (#16)

- HEVC videos (which Chromium on Linux can't decode) play through an H.264 + AAC fast-start copy
  made by ffmpeg on first open or ahead of time, cached under the data dir (`playback.*`
  settings). First open takes a few seconds while the copy is made, later opens about 0.5 s.
- The keyword index uses FTS5's `porter` stemmer and splits camelCase names, so plurals match
  ("snares" went from 0 to 18 matching files on the reviewed library), while exact codes such as
  invoice numbers and error codes still match only exactly. Search latency is unchanged.

## Everything the UI does, in the config, the CLI and the API

| UI action | config | CLI | API |
|---|---|---|---|
| Search (typing) | – | `rummage search <q>` | `POST /search {query}` |
| Kind chips | – | `--type` | `filters.types` |
| Folder filter | – | `--folder` | `filters.folders` |
| Date filter (presets, between) | – | `--after`, `--before` | `filters.date_from`, `date_to` |
| Reveal folder (search in this folder) | – | `--path GLOB` | `filters.path_glob` |
| Search by a file (drop, paste, button) | – | `--file` | `POST /search` multipart or `file` |
| More like this | – | `--similar ID` | `POST /search {item_id}`, `GET /items/{id}/similar` |
| Load more results | – | `--limit` only (no offset) | `offset` |
| Open a result (preview: details, best passages, pages, moments) | – | **`rummage item <id>`** (#12; was missing) | `GET /items/{id}?q=` |
| Thumbnail, page, frame, waveform, play | – | – (pictures and playback) | `/thumb`, `/preview`, `/waveform`, `/raw`, **`/play`** (#16) |
| Playable copies of HEVC videos (#16) | **`playback.convert`, `playback.prepare`, `playback.cache_mb`** | `config set playback.…` | `PATCH /settings`, `urls.play` |
| Open, Download, Copy path | – | path printed by `search` | `/raw` |
| Open in Files | `ui.files_url` | `config set ui.files_url` | `PATCH /settings` |
| Add a folder (path or browse) | `[[folders]]` | `folders add` | `POST /folders`, `GET /fs/dirs` |
| Remove a folder | `[[folders]]` | `folders rm` | `DELETE /folders/{id}` |
| Pause / resume one folder | `folders[].enabled` | **`folders set --off/--on`** (#12; was missing) | `PATCH /folders/{id}` |
| Exclude… on a folder | `folders[].exclude`, `include` | **`folders set --exclude/--include`** (#12; was missing) | `PATCH /folders/{id}` |
| Reindex a folder / everything | – | `reindex --folder`, `reindex` | `POST /reindex` |
| Pause / resume all indexing | – (not kept across restarts) | `index --pause/--resume` | `POST /index/pause`, `/resume` |
| Indexing progress, problems, try again | – | `status`, `status --errors`, `reindex --problems` | `/index/status`, `/index/events`, `/index/problems`, `POST /reindex` |
| Token prompt | `server.auth_token` | sent from the config (`--server` for another host) | `Authorization: Bearer` |
| Theme, recent searches | – | – | – (kept in the browser) |

Gaps left: the CLI can't page past `--limit` (no `--offset`), pausing all indexing isn't a
config key (it doesn't survive a restart), and theme and recent searches live only in the
browser. All three are low.

## Findings

| # | finding | severity | status |
|---|---|---|---|
| 1 | Audio files almost never in mixed results ("drum loop", "piano melody": none in 24) | high | fixed, #11 |
| 2 | Generic video sound tracks outranked matching frames (with `--type video` and mixed) | high | fixed, #11 |
| 3 | One sound track shared by dozens of rendered videos (and wet/dry copies of stems) filled whole pages | medium | fixed, #11 (copies go after distinct hits) |
| 4 | R4: no CLI to turn one folder off/on or edit its globs (the UI and API can) | medium | fixed, #12 |
| 5 | R4: no CLI view of one item (the UI's preview) | low | fixed, #12 |
| 6 | HEVC phone videos (33) play their sound over a still poster in Chrome on Linux, silently | medium | fixed, #13 (the player says so and suggests Download) |
| 7 | HEVC videos can't be watched in the browser on Linux at all; the server has ffmpeg and could transcode on the fly or keep an H.264 proxy | medium | fixed, #16 (an H.264 copy, made on first open or ahead of time; section 5) |
| 8 | Keyword matching doesn't stem ("claps" doesn't match `*_Clap_*.wav`, "drums" doesn't match "Drum") and needs every query word, so "hand claps" finds no stem by name. FTS5's `porter` tokenizer would handle the plurals with a keyword-index rebuild (no re-embedding); matching any word instead of all would be a separate change | medium | fixed, #16 (stemming and camelCase names; matching any word is still open; section 5) |
| 9 | Some sounds aren't told apart by the model ("hand claps", "ambient synth pad", "snare drum roll": no matching stem in the first page with either ranking) | medium | open (model limit; since #16 one-word queries find stems by name: "snares", "risers", "chords" put a right stem 2nd) |
| 10 | Served behind a reverse proxy under `/search/`, the page returned 404 until the proxy was configured | medium | fixed in the proxy configuration (search, preview, seeking, progress and Open in Files verified) |
| 11 | Video result cards asked for a 1280 px frame that ffmpeg renders on first view (50–65 KB each) instead of the 320 px window poster the indexer saves (8 KB); on a cold page this took 1.3–3.3 s and held the browser's connections, delaying the preview's media by up to 3.6 s | medium | fixed, #15 (cards use the indexed poster: 0.4 s) |
| 11b | The player's own poster is still the large frame, rendered on first open (0.4–1.3 s for that image; the video itself starts sooner) | low | open |
| 12 | Gibberish queries show 60 results with no "nothing close" hint; the calibrated scores of gibberish (0.54–0.75) overlap the weakest real queries (p10 0.61), so a score floor won't do | low | open |
| 13 | First search after a restart takes 0.5 s (vectors load, probes embed) | low | open (could warm up when the model is ready) |
| 14 | Prefix matching of the last word ("snow" finds "snowball" notes) pulls in loose keyword hits | low | open (by design for search-as-you-type) |
| 15 | R4 leftovers: CLI has no `--offset`; pause-all isn't a config key; theme and recent searches are browser-only | low | open |
| 16 | Unfiltered "screen recording of a terminal" shows notes about terminal UIs first, the screencasts from 6th place | low | open |
| 17 | The e2e test "More like this searches by the item" can check the cards before the new results replace the old ones (failed twice on #15's first CI run, passed on rerun and 5/5 locally) | low | open (test not changed here) |
